MFE Manifest Demo

Each scenario below calls newrelic.register() and/or loads a manifest-listed secondary script, mirroring tests/specs/api/register/manifest.e2e.js. Open DevTools → Network, filter by jserrors / events / ins / browser/blobs/logs, and inspect the request payloads for source.id / custom.["source.id"] to see which MFE an event was attributed to. The panel at the bottom of this page logs every action this demo takes.

1. Basic script-manifest attribution

String matcher — register an MFE whose manifest names a secondary script it never loads itself, then load that script from a real <script src> tag.

Loads js/mfe/mfe-manifest-secondary.js, which fetches, logs, and throws.

Expect: error/log/ajax from the secondary script attribute to string-matcher-mfe, not to the page/container.
RegExp matcher with type: 'script' — a RegExp matcher is never inferred as a script on its own; type: 'script' is required for it to satisfy stack-trace attribution.
Expect: same attribution as above, this time via a RegExp manifest entry.
No manifest at all (baseline) — register with no manifest option, then load the same secondary script.
Expect: the secondary script's error/log/ajax do not attribute to this MFE — only the register() caller's own activity would.
Empty manifest ({ assets: [] }) — treated identically to no manifest.
Expect: same as above — no attribution to this MFE.

2. Multiple assets / multiple MFEs

Two independent manifest-listed scripts — one MFE, manifest names two separate files.

Loads mfe-manifest-secondary.js and mfe-manifest-secondary-2.js.

Expect: errors/logs/ajax from both files attribute to the same MFE.
Two overlapping MFEs, same script — two different MFEs each list the same secondary script in their manifest.
Expect: loading the script once produces a separate, independently-attributed copy of the error for each MFE.

3. Timing & weight widening

Fetch/execute widening (timingMethod: 'scripts') — the registering call here is inline (0ms fetch/execute on its own); widening should pull those numbers from the manifest script's real network fetch/execution instead.
Expect: the next MicroFrontEndTiming insight shows timeToFetch & timeToExecute > 0, and assetUrl anchored on the secondary script.
totalWeight without timingMethod — weight accumulation is not gated behind opting into timingMethod.
Expect: totalWeight > 0 even though timeToFetch stays 0 (no widening requested).
Lazy-loaded, late-resolving asset — manifest names an image; the image is only added to the DOM 300ms after register() returns, well past the synchronous performance-buffer pass.
Expect: totalWeight > 0 anyway, via the late-resolution observer path.
Manifest asset that never loads — manifest names a file that is never added to the page.
Expect: a normal baseline MicroFrontEndTiming event still reports (no hang, no error) — timeToFetch/totalWeight stay at 0.

4. Real-world registration patterns

MFE registers itself from a real file — unlike the scenarios above (which register via an inline call on this page), mfe-manifest-root.js calls register() itself from a genuine <script src>, then a second file it names in its own manifest loads.
Expect: the secondary file's error/log/ajax still attribute correctly to manifest-root-mfe.
Platform registrar excludes itself — a "registrar" script calls register() on behalf of an MFE, with a manifest naming only the MFE's own file — never the registrar's file.
Expect: the MFE's file attributes; the registrar's own error/log/ajax never do, even though it's the one that called register().
WebSocket opened by a manifest-listed script
Expect: a WebSocket insight attributed to manifest-ws-mfe.

5. Guardrails

Non-script-only manifest, even with timingMethod: 'all' — manifest names only an image; a completely unrelated script (not in the manifest, not the caller) throws.
Expect: that error is never attributed — a manifest with zero script assets can never satisfy stack-trace matching.
timingMethod set with no manifest at all — nothing for it to widen against.
Expect: silent no-op — a normal baseline timing event, no warning/throw.
